# ISSUE-007: 강사 개별 취소 (R11)

| 항목 | 내용 |
|---|---|
| 상태 | DONE |
| 관련 FR | (선택) FR-ROM-06 (자습실 변경 시 기존 신청 처리) |

| 선행 이슈 | ISSUE-006 |

## 목표

강사가 학생의 예정 신청을 사유와 함께 취소할 수 있게 한다. 정원 축소(R6)·기간 변경(R7)이 거부되었을 때 강사가 막히지 않고, 직접 골라 취소한 뒤 다시 시도하는 흐름을 완성한다.

## 범위

- 포함
  - `POST /visits/:id/cancel`을 강사에게도 허용 (사유 필수, 소유자 검사 없음)
  - 사유 정규화(앞뒤 공백 제거, 공백뿐이면 사유 없음)
  - R6 충돌 → 강사 취소 → 재시도 흐름 e2e
- 제외
  - ISSUE-004에서 R6~R8, ISSUE-005에서 R9를 이미 구현했다 (범위 조정 기록: ISSUE-004 결정 기록)

## 완료 기준

- [x] 사유 없음·body 없음·공백뿐 → 400 `CANCEL_REASON_REQUIRED`, 아무것도 바뀌지 않음 (e2e)

## 설계 메모

ISSUE-006에서 취소 서비스를 요청자 역할과 무관하게 만들어 두었기 때문에(`checkChangeable`은 강사의 소유자 검사를 건너뜀, `actorTypeOf`가 이력 주체를 결정), 이번 변경은 정책 2개와 `@Roles` 확장이다.

```
cancel(visitId, actor, rawReason)
 ├─ reason = normalizeCancelReason(rawReason)     # "  x  " → "x", "   " → undefined
 ├─ checkCancelReason(actor, reason)              # 강사 + 사유 없음 → 400 (트랜잭션 전)
 └─ (기존) 조회 → checkChangeable → 조건부 UPDATE → 정원 복원 → 이력(actor = 요청자 역할)
```

## 결정 기록 (Decision Log)

| 날짜 | 결정 | 이유 / 검토한 대안 |
|---|---|---|
| 2026-11-15 | **학생·강사가 같은 취소 API를 씀** | 취소는 같은 상태 전이이고, 차이는 권한(소유자 검사)과 사유 필수 여부뿐이다. 엔드포인트를 나누면(`/rooms/:id/visits/:visitId/cancel` 등) 같은 상태 전이 로직이 두 경로로 갈라진다. |
| 2026-11-15 | **사유 검사를 트랜잭션 전에** | 사유 필수는 DB 상태와 무관한 입력 규칙이다. 잘못된 요청에 DB를 읽거나 쓰기 잠금을 기다리게 하지 않는다. 그래서 없는 신청에 사유 없이 요청하면 404가 아니라 400이 먼저 나간다. |
| 2026-11-15 | **사유 필수 검사를 DTO가 아니라 정책에서** | DTO는 요청자 역할을 모른다(역할은 헤더). 역할에 따라 달라지는 규칙은 정책 함수(`checkCancelReason`)에 둔다. 길이 제한(200자)처럼 역할과 무관한 형식 규칙만 DTO에 둔다. |
| 2026-11-15 | **공백뿐인 사유 = 사유 없음 (정책 추가)** | `@IsNotEmpty`는 `"   "`를 통과시킨다. 그대로 저장하면 학생 화면에 빈 사유가 보이고, 강사의 사유 필수 규칙도 무력해진다. 앞뒤 공백을 지우고 비면 없음으로 보도록 R11과 정책 문서에 추가했다. |
