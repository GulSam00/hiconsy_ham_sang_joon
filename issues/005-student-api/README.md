# ISSUE-005: 학생 API

| 항목 | 내용 |
|---|---|
| 상태 | DONE |
| 관련 FR | FR-STD-01, (선택) FR-STD-02 |
| 관련 정책 | R9 |
| 선행 이슈 | ISSUE-004 |

## 목표

강사가 학생을 조회·등록·수정·삭제할 수 있게 하고, 화면의 역할 선택(로그인 대체)에 필요한 학생 목록을 개인정보 노출 없이 제공한다. 학생 삭제 시 예정 신청을 시스템 취소해(R9) 불변 조건을 지킨다.

## 범위

- 포함
  - `GET /students/options` (공개, id·이름만), `GET /students` (강사), `POST /students`, `PATCH /students/:id`, `DELETE /students/:id` (강사)
  - 전화번호 정규화
  - R9: 삭제 시 모든 자습실의 예정 신청 시스템 취소
  - R8·R9 공통 처리를 `systemCancelUpcomingVisits()`로 추출, 자습실 삭제도 이 함수 사용
- 제외 (다른 이슈로)
  - 학생 본인의 신청 목록 → ISSUE-008

## 완료 기준

- [x] 강사는 삭제 제외 학생 전체 정보(전화번호 포함)를 이름순으로 조회, 학생은 403 (e2e)
- [x] 역할 선택용 목록은 헤더 없이 조회되고 id·이름만 담음 (e2e)
- [x] 등록·수정 시 전화번호를 `010-1234-5678` 형식으로 정규화 (단위·e2e)
- [x] 유선 번호·빈 이름·알 수 없는 필드 400, 빈 body 400, 삭제된 학생 수정 404 (e2e)
- [x] R9: 여러 자습실에 걸친 예정 신청만 시스템 취소, 지난 방문·다른 학생 신청 유지, **자습실별 `activeCount` = 실제 ACTIVE 수** (e2e)
- [x] 공통 함수 추출 후 자습실 삭제(R8) e2e가 그대로 통과 (리팩터링으로 동작 불변)
- [x] `npm run verify` 통과, 개발 서버에서 공개 목록·401·강사 목록 확인
- [x] CLAUDE.md 6·7절 갱신

## 결정 기록 (Decision Log)

| 날짜 | 결정 | 이유 / 검토한 대안 |
|---|---|---|
| 2026-11-15 | **역할 선택용 공개 API를 따로 둠 (`/students/options`, id·이름만)** | 역할 선택 화면에서는 아직 학생 id가 없어 `X-Student-Id`를 보낼 수 없다. (a) 전체 목록을 공개: 전화번호가 노출된다. (b) 화면이 강사 헤더로 목록을 조회: 역할 구분을 스스로 우회하는 셈이다. 실제 서비스의 로그인 화면처럼, 식별에 필요한 최소 정보만 공개 API로 분리했다. |
| 2026-11-15 | **R8·R9 처리를 `systemCancelUpcomingVisits()` 하나로** | 자습실 삭제와 학생 삭제는 "대상의 예정 신청을 취소하고 이력·카운터를 맞춘다"는 같은 일을 대상만 바꿔 한다. 두 벌로 두면 한쪽만 고쳐지는 일이 생긴다. 학생 삭제는 여러 자습실에 걸치므로 카운터를 자습실별로 묶어 줄인다. |
| 2026-11-15 | **전화번호는 저장 시 하이픈 형식으로 정규화** | `01012345678`과 `010-1234-5678`이 다른 값으로 저장되면 검색·중복 확인이 어려워진다. 입력은 둘 다 받고 저장 형식만 통일했다. DTO 검증과 정규화가 같은 패턴 상수를 써서 규칙이 어긋나지 않게 했다. |
| 2026-11-15 | **전화번호 중복 허용** | 형제가 보호자 번호를 같이 쓰는 경우 등 같은 번호가 정당하게 겹칠 수 있다. 과제 요구에도 유일성 조건이 없다. |
| 2026-11-15 | **학생 단건 조회 API는 만들지 않음** | 쓰는 화면이 없다. 필요해지면 추가한다. |
| 2026-11-15 | **CLAUDE.md 6절 `activeCount` 변경 지점 문장을 이 이슈에서 수정** | 이전 PR들에서 다른 PR과의 충돌을 피하려고 미뤄 둔 문장이다. 이 이슈가 바로 R9 경로로 `activeCount`를 바꾸므로 범위 안의 수정이다. |
